      Customer protection

      Disputes and reports

      "This wasn't me" claims from customers, and accounts other customers have reported. Upholding a dispute recovers whatever the recipient still holds and freezes the recipient. Decisions that move KES 10,000 or more need a second administrator.

      Feedback loop

      Models and drift

      Analyst decisions and API clients' labels become training examples. Retraining builds a challenger, which scores every payment in shadow beside the champion until you promote it or discard it. Drift compares live payments with the training data.

      Drift: population stability index by feature

      Below 0.10 stable, 0.10 to 0.25 a moderate shift, above 0.25 a major shift. Large values are expected here: the model was trained on PaySim, whose balances and amounts differ from this wallet's, and balance discrepancy is always zero in a consistent ledger.

      Red team

      Attack lab

      Runs scripted fraud scenarios through the real payment path and shows what the risk engine did with every step. Each run creates its own test accounts, so no real user is touched.

      The attack lab is switched off. Add ATTACK_LAB=1 to the .env file and restart the server to use it. Leave it off on any public deployment.

      Evaluation

      Runs every scenario and compares the engine with the model on its own. The figures describe these scenarios, which the signal weights were tuned on; they are not an estimate of real-world detection.

          Lab runs add alerts to the review queue. Removing lab data deletes the test accounts with their transactions and alerts.
          Double-entry journal

          Ledger

          Every movement of money is a journal entry whose lines add up to zero. Reconciliation proves the wallets, savings goals, loans, chamas and held payments match the journal, and that the journal and audit log have not been altered. It runs every night and on demand.

          Accountability

          Audit log

          Who did what: sign-ins, PIN and two-factor changes, freezes, alert decisions and approvals, model changes, API keys and reconciliation runs. Each record is linked to the one before it by a hash, and the database refuses to change or delete records.
